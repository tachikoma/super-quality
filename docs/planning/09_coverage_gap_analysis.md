이 3개 corp는 다른 D corp(2015~2024 전 기간 facts 보유)와 달리 facts가 부분적으로만
수집됐다:

|---|---|---|

| 085620 | 112332 | 2023~2024 |

패턴: 정식 사업보고서(예: 2016-03-30 사업보고서 2015.12)의 rcept_no가 facts에
없고, 일부 정정 보고서(예: 089860 `2022-08-12 [기재정정](2021.12)`)에만 facts가
붙어있다. 즉 2015~2020회계연도 facts 자체가 미수집 — DART API 쿼터 제한/배치
부분실패로 corp별 수집이 불균등하게 완료된 결과로 추정. `--financial-start-year 2014`
스펙 재생성만으로 해결되지 않으며, 이 corp들에 대한 별도 보강 fetch가 필요하다.

## 유니버스 확인

- 51개 전부가 2015-05-29 스냅샷(`kospi200_2015-05-29.csv`, 198종목)에 포함.
- 따라서 유니버스 누락이 아니라 데이터 갭 + proxy 특성.

## 해결 방안

1. **D 유형 (7개)**: `--financial-start-year 2014`로 배치 스펙 재생성 후 2014회계연도
   facts 수집 (DART API 키 필요). 1년 갭 4개(018260/028260/112610/204320)는 즉시 해소.
   064400/085620/089860은 2015~2020회계연도 facts가 통째로 미수집된 corp별 누락이므로
   2014 시작 스펙 + 해당 연도 보강 fetch가 모두 필요.
2. **B 유형 (9개)**: 2015-05-29 시점엔 데이터가 애초에 없으므로 수집으로 해결 안 됨.
   첫 리밸런스를 quality 없이 진행하거나(현재 partial-fill 모드), 유니버스 PIT 구성
   개선 필요.
3. **C 유형 (35개)**: 유니버스 proxy 특성. 역사적 KOSPI 200 구성원 데이터로 유니버스를
   PIT화해야 해결. 수집 스펙 문제가 아님.
4. **근본 개선**: DART 스펙 생성 시 `financial-start-year`를 WF 시작연도 - 1로 설정해
   시장 전방(lookahead) 없이 첫 리밸런스에 이전 회계연도 데이터가 있도록 보장하고,
   corp별 fetch 완료 여부(bsns_year/period_end 커버리지)를 수집 후 검증한다.
